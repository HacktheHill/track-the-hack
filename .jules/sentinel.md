## 2024-10-24 - Missing Authorization in `users.search`
**Vulnerability:** The `users.search` tRPC endpoint was only protected by authentication (`protectedProcedure`) without an explicit role check. This allowed any authenticated user to retrieve details (names, emails) of other users.
**Learning:** In this tRPC setup, `protectedProcedure` only guarantees authentication. It does not enforce role-based access control (authorization) out of the box unless explicitly checked within the procedure.
**Prevention:** Always verify if a `protectedProcedure` requires specific roles (like `ADMIN` or `ORGANIZER`) and use the `hasRoles` utility combined with `ctx.prisma.user.findUnique` to enforce these constraints. Additionally, ensure correct error propagation using `TRPCError`.
## 2024-10-24 - Missing Authorization in `auditLog` router
**Vulnerability:** The `new` and `all` tRPC endpoints were only protected by authentication (`protectedProcedure`) without an explicit role check. This allowed any authenticated user to create or retrieve audit logs. Also, it returned generic generic errors which may leak internal information.
**Learning:** `protectedProcedure` only guarantees authentication. It does not enforce role-based access control (authorization) out of the box unless explicitly checked within the procedure. Additionally, instantiating new `PrismaClient` instances inside routers defeats connection pooling, instead the injected context `ctx.prisma` must be used.
**Prevention:** Always verify if a `protectedProcedure` requires specific roles (like `ADMIN` or `ORGANIZER`) and use the `hasRoles` utility combined with `ctx.prisma.user.findUnique` to enforce these constraints. Additionally, ensure correct error propagation using `TRPCError` to prevent stack trace leaks, and always use `ctx.prisma` for database access.
