## 2024-10-24 - Missing Authorization in `users.search`
**Vulnerability:** The `users.search` tRPC endpoint was only protected by authentication (`protectedProcedure`) without an explicit role check. This allowed any authenticated user to retrieve details (names, emails) of other users.
**Learning:** In this tRPC setup, `protectedProcedure` only guarantees authentication. It does not enforce role-based access control (authorization) out of the box unless explicitly checked within the procedure.
**Prevention:** Always verify if a `protectedProcedure` requires specific roles (like `ADMIN` or `ORGANIZER`) and use the `hasRoles` utility combined with `ctx.prisma.user.findUnique` to enforce these constraints. Additionally, ensure correct error propagation using `TRPCError`.

## 2024-10-24 - Missing Authorization leading to IDOR/Info Disclosure in `events` tRPC public procedures
**Vulnerability:** The `events.all`, `events.get`, and `events.future` tRPC endpoints were implemented as `publicProcedure`s and did not explicitly filter out hidden events on the backend unless accessed by an organizer. Although the frontend conditionally filtered out `event.hidden` for public users, a malicious user or unauthenticated client could directly invoke the tRPC endpoints and retrieve full details about hidden events, leading to an Information Disclosure/Insecure Direct Object Reference (IDOR) vulnerability.
**Learning:** Returning unfiltered sets of data from public endpoints and relying on frontend client logic to hide sensitive/hidden records is an anti-pattern. NextAuth populates `ctx.session.user.roles` with `RoleName[]`, so authorization rules (e.g. `isOrganizer`) can be cheaply evaluated even in `publicProcedure`s without extra database hits.
**Prevention:** Always verify if a `publicProcedure` is returning potentially sensitive subset of records (like `hidden: true`). Enforce data restrictions on the backend using Prisma's `where` clause combined with session role checks (e.g., `where: isOrganizer ? undefined : { hidden: false }`), ensuring hidden data never crosses the network for unauthorized users.
