## 2025-03-05 - Add ARIA Roles and Focus States to Tabs
**Learning:** Adding ARIA roles to interactive custom components like Tabs helps screen readers appropriately interpret and present the components correctly. But more specifically to this codebase, 'roving tabindex' (`tabIndex={-1}`) should only be used when implementing custom keyboard navigation (e.g. up/down/left/right arrow keys) for a specific active element within a widget. Since custom keyboard handlers are not present in this Tabs component, the native focusability is preserved for all tab buttons to prevent blocking keyboard-only navigation.
**Action:** When working on interactive widgets (e.g., Tabs) that do not have explicitly implemented custom keyboard navigation, use focus ring styling (e.g., `focus-visible:ring-2 focus-visible:outline-none`) and avoid setting `tabindex="-1"`. Ensure explicit ARIA roles are added (`tablist`, `tab`, `tabpanel`) for accurate semantic structure for assistive technologies.
