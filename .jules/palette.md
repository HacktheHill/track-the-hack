## 2024-06-25 - Custom Interactive Components and Accessibility
**Learning:** In this Next.js app, interactive custom components like Tabs are frequently built with non-semantic HTML structures (e.g., using a group of generic buttons without `role="tablist"`/`role="tab"` and missing focus outlines). This breaks keyboard navigation flow and leaves screen reader users without proper context of the component structure.
**Action:** When working on custom interactive elements across the app, always add explicit ARIA roles (e.g., `role="tablist"`, `role="tab"`, `role="tabpanel"`) and use explicit Tailwind focus ring classes (`focus-visible:ring-2 focus-visible:outline-none`) to ensure keyboard navigability and screen reader support. Care must be taken not to trigger global formatting scripts to prevent noisy commits.
